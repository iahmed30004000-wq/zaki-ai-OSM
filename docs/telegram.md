# تكامل تيليجرام (Telegram → Orders)

تحويل رسائل مجموعات تيليجرام المرتبطة بالنظام إلى طلبات (Orders) تلقائيًا عبر Webhook مباشر إلى Zaki Backend — بدون n8n أو خدمات وسيطة.

## المسار

```
Telegram Group/Topic → Bot → Webhook → /api/webhooks/telegram
  → Secret verification (timing-safe) → Source resolution (topic → group)
  → Idempotency (DB unique) → Parser → Validation → Product matching
  → Order creation (same transactional logic as the manual API)
```

## 1. إنشاء البوت

1. افتح [@BotFather](https://t.me/BotFather) وأرسل `/newbot` واتبع الخطوات.
2. احفظ التوكن (يبدأ عادةً بـ `123456:AA...`) — يوضع في `TELEGRAM_BOT_TOKEN` فقط على السيرفر.

## 2. إضافة البوت إلى المجموعة

1. أضف البوت إلى المجموعة/الـ Supergroup.
2. تأكد أن البوت يستطيع قراءة الرسائل: من BotFather → `/setprivacy` → اختر **Disable** (أو امنح البوت صلاحية قراءة الرسائل في المجموعة). في المجموعات ذات المواضيع (Forum) تأكد أن الرسائل تصل للبوت.

## 3. الحصول على Chat ID

- أرسل رسالة في المجموعة، ثم استخدم `https://api.telegram.org/bot<TOKEN>/getUpdates` وابحث عن `chat.id` (يبدأ عادةً بـ `-100`).
- أو استخدم بوتات معروفة مثل `@RawDataBot` لقراءة `chat.id`.

## 4. الحصول على Topic ID

في مجموعة Forum: أرسل رسالة في الموضوع المطلوب، وستجد `message_thread_id` في الـ update. لربط المجموعة بالكامل اترك الـ Topic ID فارغًا.

## 5. متغيرات البيئة

```env
TELEGRAM_BOT_TOKEN="<من BotFather>"
TELEGRAM_WEBHOOK_SECRET="<openssl rand -hex 32>"
TELEGRAM_ENCRYPTION_KEY="<openssl rand -hex 32>"
APP_URL="https://<نطاق-النظام>"
```

## 6. إعداد الويبهوك

- من صفحة `/dashboards/telegram/settings` اضغط **تسجيل / تحديث الويبهوك** (يتطلب `telegram.manage`).
- أو يدويًا:
  ```
  https://api.telegram.org/bot<TOKEN>/setWebhook?url=<APP_URL>/api/webhooks/telegram&secret_token=<SECRET>
  ```

## 7. إضافة Source

- `/dashboards/telegram` → **إضافة مجموعة** → أدخل Chat ID (و Topic ID اختياريًا).
- الشركة تُحدد تلقائيًا من جلسة المستخدم (لا يمكن إرسالها من الواجهة).

## 8. اختبار طلب

في شكلين للرسالة. أي واحد منهم بيصير طلب لحالو.

### الشكل الأول: سطر لكل معلومة (7 أسطر بالترتيب، بلا عناوين)

```
26818
2026-10-28 15:40:01
محمد
0932323642
سوريا حماه
ماء الكمأ الأصلي
القطعة ب 15 $ + توصيل مجاني
```

| السطر | شو هو | شو بيصير فيه |
|---|---|---|
| 1 | المرجع | ما بينكتب بأي حقل بالطلب. بينحفظ بالملاحظات الداخلية «مرجع المصدر: …»، وهو مع السطر 2 مفتاح التكرار |
| 2 | تاريخ الطلب بالمصدر | لازم يكون تاريخ حقيقي (مثل `2026-10-28 15:40:01`)، من أسبوع قبل وصول الرسالة لحد يوم بعدها. بينحفظ نص بالملاحظات «وقت الطلب بالمصدر: …» وبيطلع بالشاشة «تاريخ الطلب». وقت الطلب بالنظام (`createdAt`) بيضل وقت وصول الرسالة |
| 3 | العميل | حرفين عالأقل، بلا أرقام، 80 حرف بالأكتر |
| 4 | الهاتف | أرقام و `+` ومسافات و `-` و `( )` بس، ولازم يكون رقم صالح لبلد المتجر |
| 5 | المحافظة | إذا أولها اسم بلد المتجر (سوريا / سورية / سوريه) بينشال. اسم بلد تاني → مراجعة. الباقي بيتطابق مع مناطق البلد متل قبل، وإذا ما انعرف بينعمل الطلب بلا منطقة |
| 6 | المنتج | من منتجات **هاد المتجر** الفعّالة بس: مطابق، أو منتج واحد بيحتوي الاسم. التخمين → مراجعة |
| 7 | العرض | `القطعة / القطعتين / 3 قطع` + `ب` + **الإجمالي** + العملة (اختياري) + `توصيل مجاني` (اختياري) |

سطر العرض:

- الرقم هو **إجمالي** هالقطع، وما بينضرب بالكمية أبداً: «القطعة ب 15» = قطعة بـ15، «القطعتين ب 25» = قطعتين بـ25 (القطعة 12.5).
- «توصيل مجاني» أو «التوصيل مجاني» أو «شامل التوصيل» = سعر هالطلب شامل التوصيل، متل عرض فيه التوصيل: الكابتن بيحصّل الإجمالي، والأجرة بتنحسب علينا. بلاها بتمشي سياسة المتجر متل قبل.
- رقم جنب «توصيل» (مثل «+ 3 $ توصيل») → مراجعة: الأجرة من جدول المناطق مش من الرسالة.
- عملة غير عملة المتجر → مراجعة، وما في تحويل. بلا عملة = عملة المتجر.
- فاصلة بالرقم («15,000») أو رقم تاني أو كلمة زيادة أو «هدية» → مراجعة.

أي رسالة بهالشكل ما بترجع للقارئ القديم، وما بتنحط «متجاهلة» لحالها: إذا سطر فيها غلط بتروح للمراجعة والسبب بيسمّي السطر.

### الشكل الثاني: بالعناوين (متل قبل)

```
طلب جديد
الاسم: أحمد
الهاتف: 0933444555
العنوان: عرفات
المنتج: <اسم منتج موجود في النظام>
الكمية: 2
السعر: 30 $
```

بلا سطر «السعر:» الرسالة بتروح للمراجعة (السعر ناقص) — سعر المنتج الأساسي ما بينحط بدالو.

يجب أن يظهر الطلب في `/orders` بمصدر **Telegram**، وعلى شاشة «طلبات تلجرام» تحت «صارت طلبات». الرسالة اللي ما انقرأت بتطلع تحت «للمراجعة» والسبب بيسمّي السطر.

## استكشاف الأخطاء

| المشكلة | السبب المحتمل |
|---|---|
| لا تصل أي رسائل | الويبهوك غير مُسجل أو السر غير مطابق أو البوت ليس في المجموعة |
| الحالة "تحتاج مراجعة" | المنتج غير موجود/غامض، رقم غير صالح، بيانات ناقصة — السبب ظاهر بجانب الحالة |
| `Forbidden` في السيرفر | `X-Telegram-Bot-Api-Secret-Token` لا يطابق `TELEGRAM_WEBHOOK_SECRET` |
| الرسائل لا تُحوَّل لطلبات | المجموعة غير مفعلة (isActive) أو Topic ID خاطئ |

## الأمان

- التحقق من السر بمقارنة timing-safe → 403 عند الفشل.
- Idempotency عبر قيد فريد في قاعدة البيانات (`companyId + chatId + messageId`) — نفس رسالة تيليجرام لا تنشئ طلبًا مرتين.
- السعر هو **الإجمالي المكتوب بالرسالة** (سطر «السعر:» أو السطر 7)، والسيرفر بيتحقق منه (رقم موجب، 100,000 بالأكتر، بخانات عملة المتجر) وبيقسمه عالكمية بلا تقريب. ما بيُوخذ من `product.basePrice` أبداً: رسالة بلا سعر بتروح للمراجعة.
- المتجر والشركة من المجموعة المربوطة بالنظام، مش من الرسالة. ونفس الرسالة ما بتعمل طلبين: الربط بين الرسالة وطلبها بينكتب جوّا نفس العملية.
- العزل بين الشركات (tenant isolation) مفروض في كل الاستعلامات والـ APIs.
- لا تُعرض أو تُسجَّل أي مفاتيح سرية في أي استجابة أو سجل.
